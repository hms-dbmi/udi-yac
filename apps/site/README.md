# udi-yac-site

The landing page and docs for YAC, built with [Astro Starlight](https://starlight.astro.build/). `.github/workflows/pages.yml` publishes it at [hms-dbmi.github.io/udi-yac](https://hms-dbmi.github.io/udi-yac/), together with two other apps from this repo. They are separate builds that `pages.yml` copies into one artifact:

| Path                | What         | Source                       |
| ------------------- | ------------ | ---------------------------- |
| `/udi-yac/`         | Landing page | `src/content/docs/index.mdx` |
| `/udi-yac/docs/…`   | Docs         | `src/content/docs/docs/`     |
| `/udi-yac/app/`     | The chat     | `packages/chat` (standalone) |
| `/udi-yac/grammar/` | Grammar demo | `apps/grammar-app`           |

## Local development

Locally, the landing page and docs are one dev server, and the chat and the grammar demo are two more. The site's dev server proxies `/udi-yac/app/` and `/udi-yac/grammar/` to the other two. **A link into the app or the grammar demo only works while that server is running.** If it isn't, the proxy answers with a page that names the task to start.

The VS Code tasks (**Terminal → Run Task…**) start the right combination:

| Task                 | Starts                                                                                           | Serves                               |
| -------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------ |
| **Dev: all**         | everything below                                                                                 | the whole site, as Pages lays it out |
| **Dev: site**        | Dev: site docs + Dev: site app                                                                   | landing, docs and `/udi-yac/app/`    |
| **Dev: site docs**   | this package, `:4321`                                                                            | landing and docs only                |
| **Dev: site app**    | the chat under `/udi-yac/app/`, `:5176`; opens on pcx in browser mode whatever `.env.local` says | `/udi-yac/app/`                      |
| **Dev: grammar app** | the grammar demo, `:9000`                                                                        | `/udi-yac/grammar/`                  |
| **Dev: agent**       | the agent server, `:8007`                                                                        | asking questions in the chat         |

Open <http://localhost:4321/udi-yac/>. Browsing a predefined session needs no agent; asking a question does.

Without VS Code, run each in its own terminal from the repo root:

```bash
pnpm dev:site                                    # landing + docs, :4321
VITE_BASE=/udi-yac/app/ VITE_UDI_DATA_PACKAGE=/udi-yac/app/data/pcx/datapackage.json \
  VITE_UDI_REMOTE_PACKAGE= pnpm --filter udi-yac dev --port 5176 --strictPort   # chat, :5176
pnpm dev:grammar                                 # grammar demo, :9000
pnpm dev:agent                                   # agent, :8007
```

The proxy expects the chat on `:5176` and the grammar demo on `:9000`. If either port is taken, the server lands elsewhere and the proxy won't find it. **Dev: chat** (`:5173`, at `/`) is separate and unaffected: use it for quick iterations on the chat alone.

Astro 7 starts `astro dev` in the background when it isn't attached to a terminal. If port `:4321` stays taken after you stop the task, run `pnpm --filter udi-yac-site exec astro dev stop`.

To check the real thing, build all three and assemble them the way `pages.yml` does (`_site/`, `_site/app/`, `_site/grammar/`), then serve the parent of a directory named `udi-yac` that holds them.

## Where the content comes from

- `src/content/docs/docs/using/`: user docs, written by hand.
- `src/content/docs/docs/integrate/` and `docs/charts.md`: generated by `scripts/sync-docs.mjs` on every dev and build run, and gitignored.
  - The integrate pages are copied from the package READMEs. Relative links become GitHub URLs, or site links when they point at another synced README.
  - The chart gallery is built from the agent's `template_visualizations.json`.
  - **Edit the source, not these pages.**
- `src/content/docs/docs/api/`: generated by `starlight-typedoc` from `packages/chat/src/index.ts` on every dev and build run, and gitignored. It needs the toolkit's `dist/` (`pnpm build:toolkit`).
- The dataset cards on the landing page read `sample-data/catalog.json`, the same list the app's dataset switcher uses.

Starlight doesn't prefix links written in markdown with `base`, so links in the content spell out `/udi-yac/…`.
